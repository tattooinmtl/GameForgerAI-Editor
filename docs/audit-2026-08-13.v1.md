## Critical — build-breaking / data loss / security

### C1. Runtime does not build against the current Engine header
**File:** `Runtime/src/main.cpp:442-464` vs `Engine/include/GameForger/Editor/ScriptRuntime.hpp:84-93`

The header declares 9 parameters for `ScriptRuntime::initialize`:
```
EditorScene& scene
AICommandBus& commandBus
InputSource& inputSource
LogCallback
ProjectileSpawnCallback
BoolQueryCallback  // heldItemQuery
BoolQueryCallback  // aimingCatapultQuery
BoolSetCallback    // operatingCatapultSet
GravityProjectileSpawnCallback
```

The Runtime call passes only 7. The Editor passes all 9. **The standalone game target literally does not compile.** File timestamps confirm `ScriptRuntime.hpp` was modified after `Runtime/src/main.cpp`. Last successful build of `GameForgerRuntime.exe` predates the header change.

**Fix:** add the missing two stubs in the Runtime call:
```cpp
[](const bool) { /* Runtime has no catapult UI */ },
[](const glm::vec3&, const glm::vec3&, float, const std::string&){ /* no-op */ });
```

### C2. Scene saves are destructive and non-atomic
**File:** `Engine/src/Editor/SceneSerializer.cpp:552-563`

`saveScene` opens the destination with `std::ios::trunc` and writes directly. Any crash mid-write leaves the scene truncated. The previous audit called this out; the code is unchanged. Same bug in `EditorScene::CreateScriptCommand` at `Engine/src/Editor/EditorScene.cpp:108-113` — `std::ofstream(..., std::ios::trunc)` silently overwrites existing scripts without warning.

**Fix:** temp-file + flush + close + atomic `rename()`; refuse overwrite on existing script files.

### C3. WinHTTP 120-second blocking shutdown — no cancellation
**File:** `Editor/src/AIProviderClient.cpp:164` + `Editor/src/main.cpp:6882-6892`

Hard-coded 120 s timeout on every WinHTTP phase. Worker threads have no atomic stop flag, no cancel handle. Closing the window during an in-flight request blocks the main thread on `worker.join()` for up to two minutes. Worse, starting a new "Generate" / "Plan" click while the previous worker is still running blocks the UI thread on the old join.

**Fix:** add `std::atomic<bool> stopRequested` per worker, share a cancellable `HINTERNET` handle, drop timeouts to 15-30 s, bound the join with a short wait.

### C4. Provider/response parsing uses literal substring search
**File:** `Editor/src/AIProviderClient.cpp:37-58, 94-128`, `Editor/src/AIChatResponse.cpp:87-124`

`parseProvider` still does `configuration.find("\"id\": \"" + providerId + "\"")` then extracts values between the next two `"`. Concretely broken:
- A description string containing the substring `"endpoint"` is matched as the endpoint field.
- Escaped `\"` inside URLs terminates the value prematurely; `WinHttpConnect` then fails on a backslash-laden host name.
- The model name is concatenated raw into the request body with no escaping (a `"` or `\n` in a model name produces an invalid JSON body).
- `extractChatMessageContent` returns the *first* `"content"` substring anywhere — wrong for streaming, wrong for non-OpenAI shapes, wrong when an error response has `error.message`.
- `extractErrorMessage` on a successful response returns the literal text of the next key inside `choices[0].message` (e.g., the string `"content"`) as the "error".

**Fix:** replace with the structured `json::Value` parser that's already in the Engine; structurally walk `providers[]` / `choices[0].message.content` / `error.message`.

## High — visible wrong behavior in normal use

### H-Script-1. `luaEntityGetRight` returns the *left* vector
**File:** `Engine/src/Editor/ScriptRuntime.cpp:117-125`

```cpp
const glm::vec3 forward(std::sin(yawRadians), 0.0F, std::cos(yawRadians));
pushVec3(L, glm::normalize(glm::cross(forward, glm::vec3(0.0F, 1.0F, 0.0F))));
```
With yaw=0: forward=(0,0,1); `cross(forward, +Y) = (-1, 0, 0)`. Right-handed convention (Y up, Z forward) requires `right = +X = cross(+Y, forward)`. **Every FPS / third-person Lua script strafes backwards relative to the on-screen right.** `Game/Scripts/fps_controller.lua:88-91` reads `right.x * strafe_axis`, so pressing D moves the player in −X while facing +Z.

**Fix:** swap operands to `glm::cross(glm::vec3(0,1,0), forward)`.

### H-Play-1. Animation overwrites parent-constraint — parented animated entities detach
**File:** `Engine/src/Runtime/GameplayLoop.cpp:59-106`

Both `applyParentConstraints` and `tickPlayModeAnimations` execute the *same* command for animated parented entities:
```
SetPropertyCommand{entity.name, "Transform", "position", newPosition}
```
The animation runs after the parent resolver in the same frame, so the world transform derived from the parent is discarded. The Castle scene's animated turrets/catapult arms visibly detach from their pivots.

**Fix:** write animated parented entities' keyframes to `localPosition`/`localRotationEuler`/`localScale` and let `applyParentConstraints` compose the world. Or skip animation for entities with non-empty `parentName`.

### H-Render-1. All STB-loaded textures are flipped vertically
**File:** `Engine/src/Editor/TerrainTexture.cpp:81-100` + every other `stbi_load` site

No `stbi_set_flip_vertically_on_load(true)` call anywhere in the codebase (verified via grep). OpenGL's `glTexImage2D` interprets the first byte as the bottom row, but STB returns top-row-first. Every diffuse, normal, and heightmap texture sampled in the editor appears upside-down versus its source art. Invisible for directionless textures, wrong for any art with text, characters, grass tufts, footprints, brick courses.

**Fix:** call `stbi_set_flip_vertically_on_load(true)` once in static init, or flip rows before upload.

### H-Edit-1. AI Animation bypasses the undo system
**File:** `Editor/src/main.cpp:5827-5835`

```cpp
if (SceneEntity* mutableEntity = scene.findEntityMutable(target->id)) {
    mutableEntity->animation.enabled = true;
    mutableEntity->animation.looping = generated.looping;
    mutableEntity->animation.keyframes = generated.keyframes;
}
```
Direct mutation; no command bus, no undo snapshot. After "Apply", Ctrl+Z (when wired) will not revert the AI-applied animation, and the undo stack is silently inconsistent.

**Fix:** wrap as a new `SetAnimationCommand` variant, route through `commandBus.execute`, register a validator.

### H-Edit-2. Save Scene menu advertises `Ctrl+R` but only `Ctrl+N` / `Ctrl+O` have key handlers
**File:** `Editor/src/main.cpp:1429` + `:1419-1429`

`ImGui::MenuItem("Save Scene", "Ctrl+R")` — the second argument is a display string only. No `io.KeyCtrl && ImGui::IsKeyPressed(ImGuiKey_R)` branch exists. Pressing Ctrl+R does nothing. The user-visible promise doesn't match reality.

**Fix:** add a key handler for Ctrl+R (or, better, switch the label to Ctrl+S and wire it).

### H-Edit-3. Edit > Undo / Edit > Redo menu items are inert
**File:** `Editor/src/main.cpp:1477-1478`

```cpp
ImGui::MenuItem("Undo", "Ctrl+Z");
ImGui::MenuItem("Redo", "Ctrl+Y");
```
Return values discarded. `performUndo`/`performRedo` exist but aren't called from the menu. Ctrl+Z / Ctrl+Y are also no-ops.

**Fix:** `if (ImGui::MenuItem(...)) { performUndo(history, scene, selection); }` for each, and add the matching key handlers.

### H-Edit-4. AI Setup "Calibrate / Test provider" button is a no-op
**File:** `Editor/src/main.cpp:1739-1742`

```cpp
if (ImGui::Button("Calibrate / Test provider")) {
    state.calibrated = true;
    state.setupChanged = false;
}
```
Flips two UI flags and does nothing else — no test request, no endpoint probe, no API key validation. The `state.endpoint` / `state.model` edits in this panel are also ignored by `AIProviderClient`, which still re-reads `Providers.json` on every call. Users see "Calibrated ✓" while their overrides have no effect.

**Fix:** send a lightweight GET request and surface status; plumb override settings through to the client.

### H-Render-2. Capsule bottom hemisphere lighting is inverted
**File:** `Engine/src/Editor/PrimitiveMeshes.cpp:181`

```cpp
generateUvSphereShell(out, 8, segments, -radius, -halfHeight);
```
The negation produces the correct *shape* (a sphere of radius 0.5 at the bottom) but the unit-vector normals computed inside `generateUvSphereShell` then point **inward** toward the sphere center. Visible as "inside-out" lighting on the bottom half of every capsule primitive.

**Fix:** drop the negation — `generateUvSphereShell(out, 8, segments, radius, -halfHeight);`.

### H-Render-3. Winding-order inversion across most primitives
**File:** `Engine/src/Editor/PrimitiveMeshes.cpp` (cube ±X faces, sphere, cylinder side+disks, cone slant+base, capsule body)

Cross-product of (b−a) × (c−a) for the first triangle of most faces points *opposite* to the declared `normal` attribute. Latent today because `GL_CULL_FACE` is disabled — the shader uses the declared attribute, so the user sees the correct normal lighting. The moment culling is enabled (or any shader consults `gl_FrontFacing`), most geometry disappears.

**Fix:** swap vertex order so right-hand-rule matches the declared normal; flip `reverseWinding` flag on the cylinder top disk.

### H-Edit-5. Rename/Delete silently break parent→child links
**File:** `Engine/src/Editor/EditorScene.cpp:39-69`

`RenameEntityCommand` writes the new name and reports success, but every other entity whose `parentName == oldName` becomes an "orphan" per the class's own contract. `DeleteEntityCommand` has the same shape. The editor looks correct; parented transforms stop following silently.

**Fix:** after renaming, rewrite any matching `parentName` to the new value and report the count. Before deleting, clear children's `parentName` (or move them to root with preserved transforms).

### H-Script-2. No Lua instruction budget — infinite loop freezes editor
**File:** `Engine/src/Editor/ScriptRuntime.cpp` (whole file)

Zero `lua_sethook` calls (verified). A `while true do end` in `on_update` blocks `lua_pcall` until the process is killed. The 2026-08-02 audit called this out under H2; it remains unaddressed.

**Fix:**
```cpp
lua_sethook(state_, hookFn, LUA_MASKCOUNT, 100000);
```
plus a memory cap via `lua_setallocf` and a repeated-error cutoff.

### H-Edit-6. AI worker exceptions strand "generating"/"planning" flag
**File:** `Editor/src/main.cpp:5028-5036, 5787-5795, 6281-6290`

The atomic `generating`/`planning` flag is reset only on the success path. If `generateAnimation` / the planner ever throws (`std::bad_alloc`, JSON parser exception, WinHTTP `system_error`), the UI shows "Generating..." forever and the worker handle stays joinable.

**Fix:** wrap the worker body in `try { … } catch (...) { /* write failure result under lock */ }` or a scope guard.

## Medium — edge cases / robustness

### E-Render-1. Material cache leaks GPU textures on entity deletion
**File:** `Engine/src/Editor/ViewportRenderer.cpp:702-755, 1519`

The per-frame pruning loops iterate `textMeshCache_`, `terrainCache_`, `importedMeshCache_` and free GL handles for deleted entities. `materialCache_` is **not** pruned — only `shutdown()` clears it. Deleting a textured primitive leaks 9 GL textures (3 layers × diffuse/normal/height) per entity until process exit.

**Fix:** add a third pruning loop mirroring the existing three.

### E-Render-2. TextMesh hole contours: side-wall normals point into the solid
**File:** `Engine/src/Editor/TextMesh.cpp:506-515`

`classifyAndNormalizeContours` marks outer contours CCW and hole contours CW. The wall-normal code uses the same right-perpendicular for every edge. For CW hole contours the "outside-air" direction is the **left**-perpendicular, so the side walls of every glyph hole (A, O, 8, P, R, B…) light from the wrong side.

**Fix:** flip normal for hole contours:
```cpp
const glm::vec3 normal(contour.isHole ? -edgeDirection.y : edgeDirection.y,
                       contour.isHole ?  edgeDirection.x : -edgeDirection.x,
                       0.0F);
```

### E-Render-3. Cone normal uses a hardcoded `0.5F` magic number
**File:** `Engine/src/Editor/PrimitiveMeshes.cpp:168`

```cpp
const glm::vec3 normal = glm::normalize(glm::vec3(std::cos(amid), 0.5F, std::sin(amid)));
```
This happens to match `radius = 1` / apex y=1 / base y=−1 today. The instant anyone tweaks the cone geometry, the constant silently produces wrong shading.

**Fix:** derive from geometry: `glm::normalize(glm::vec3(std::cos(amid) * radius, apex.y - baseY, std::sin(amid) * radius));`

### E-Scene-1. `loadScene` ignores `format` and `version`
**File:** `Engine/src/Editor/SceneSerializer.cpp:566-585`

The writer embeds `"format": "GameForgerScene"`, `"version": 8`. The loader ignores both. Any JSON file with an `entities` array (Project.json, package manifests, third-party JSON) loads as a scene with default-fallback fields and silently overwrites the current scene via `EditorScene::loadEntities()`.

**Fix:** validate `format == "GameForgerScene"`; reject/upgrade on version mismatch.

### E-Json-1..6. JSON parser accepts invalid input
**File:** `Engine/src/Editor/Json.cpp`

Six distinct acceptance failures verified:
- **E-Json-1:** `parseDocument` doesn't require end-of-input → `{"foo":1}garbage` parses.
- **E-Json-2:** `parseRawString` accepts a trailing `\` (no next char) as a literal backslash.
- **E-Json-3:** Raw control characters U+0000–U+001F accepted inside strings.
- **E-Json-4:** `\u` escapes: no hex validation (strtoul silently stops), no surrogate pair handling, lone surrogates emitted as invalid UTF-8.
- **E-Json-5:** `appendUtf8` has no 4-byte branch — needed once surrogate pairs are fixed.
- **E-Json-6:** `parseNumber` accepts leading `+`, structurally lax loop accepts `1.2.3`, `--5`, etc.

### E-Scene-2. `escapeJson` silently drops `\r` and other control bytes
**File:** `Engine/src/Editor/SceneSerializer.cpp:306-323`, `Editor/src/AIProviderClient.cpp:72-92`

Both escape implementations drop `\r` silently and let `\t`, `\b`, `\f`, `\0`, etc. through as raw bytes — invalid JSON. User-pasted CRLF strings lose CR on round-trip; pasted tabs/form-feeds produce invalid JSON.

### E-Script-1. `startScript` can double-register the same script
**File:** `Engine/src/Editor/ScriptRuntime.cpp:762-763`

No membership check before pushing onto `instancesByEntity_[entityId]`. `AttachScriptCommand` guards at attach-time, but `startScript` is `public`; any code path that calls it twice (retry after transient load, attach during play) silently runs two `on_update` loops in parallel on the same entity.

### E-Script-2. `getScriptNumberField` is `const` but mutates the Lua stack
**File:** `Engine/src/Editor/ScriptRuntime.cpp:839-865`

`const` qualifier hides the fact that `lua_rawgeti` / `lua_getfield` / `lua_pop` mutate the VM. Compiles and works in single-threaded code; sets a foot-gun for future multi-threaded readers who assume `const` = no side effects.

### E-Script-3. `CreateScriptCommand` silently overwrites existing scripts
**File:** `Engine/src/Editor/EditorScene.cpp:108-113`

`std::ofstream(*scriptPath, std::ios::binary | std::ios::trunc)` overwrites without warning. If Play is running, the Lua chunk in the registry still references the old function objects; edits don't take effect until Play restarts.

### E-Scene-3. `DuplicateEntityCommand` doesn't bring children along
**File:** `Engine/src/Editor/EditorScene.cpp:70-83`

The copy preserves `parentName` and `scripts` but not descendants. After duplication, the source's children still point at the original name; the duplicate is a leaf. User-visible inconsistency depending on which name appears first.

### E-Validate-1. `SetPropertyCommand` accepts NaN/Inf and wrong types silently
**File:** `Engine/src/Editor/EditorScene.cpp:337-613`, `Engine/src/Editor/AICommandBus.cpp:112-121`

`SetPropertyCommand{entityName, "Transform", "position", std::string("foo")}` returns "This scene property is not implemented yet" instead of "value type mismatch." Vec3 fields accept NaN/Inf — `glm::translate` propagates NaN into the model matrix. `SetPropertyCommand` validator doesn't finiteness-check vec3s the way `SetPositionCommand` does.

### E-Validate-2. Validator default branch silently approves unknown commands
**File:** `Engine/src/Editor/AICommandBus.cpp:148-151`

If a new command variant is added without a validator case, the catch-all returns `{success=true}`. AI then learns "command accepted" but execution returns generic failure. The AI can't tell unimplemented from rejected.

### E-Validate-3. `AttachScriptCommand` validator inconsistent with `CreateScriptCommand`
**File:** `Engine/src/Editor/AICommandBus.cpp:88-93`

`CreateScriptCommand` rejects `..` in the path. `AttachScriptCommand` doesn't, although the executor does its own check via `resolveProjectFile`. Preview and execute disagree.

### E-Animation-1. Linear interpolation on Euler angles
**File:** `Engine/src/Editor/Animation.cpp:49-51`

```cpp
pose.rotationEuler = glm::mix(start.rotationEuler, end.rotationEuler, alpha);
```
For a 0°→350° rotation, the entity spins the long way around (360°) instead of the 10° shortcut. Should slerp quaternions.

### E-Animation-2. Boundary `<=` causes first-of-two-segments to win on keyframe hit
**File:** `Engine/src/Editor/Animation.cpp:44`

When `sampleTime == keyframes[i].time`, both segments i−1 and i match; the loop picks the earlier one. Subtle inconsistency with timeline scrub UX.

### E-Animation-3. Imported `AnimationClip` lacks a `looping` field
**File:** `Engine/include/GameForger/Editor/ModelImport.hpp:54-59` vs `Engine/include/GameForger/Animation/AnimationClip.hpp:39`

Imported clips always loop (`std::fmod(time, duration)`); the structured `AnimationClip` has a `looping` flag. Non-looping rigged imports cannot be authored.

### E-Run-1. Win/lose banner never shown to the player
**File:** `Engine/src/Runtime/GameplayLoop.cpp:174-186` vs `Runtime/src/main.cpp`

`GameplayState::gameOverMessage` is set when a castle's HP reaches 0; the Editor renders it via ImGui. The Runtime has zero consumers — a runtime player who wins or loses gets no feedback.

### E-Run-2. Unclamped delta time corrupts physics on tab-out / breakpoint
**File:** `Runtime/src/main.cpp:497-499` → `GameplayLoop`

`deltaTime` is the raw `glfwGetTime` difference handed straight to gravity (`-18 m/s²` and `-20 m/s²` for catapult). A 5-second tab-out makes the player tunnel through floors and castle colliders in one frame. Editor's `drawGameViewPanel` is also exposed.

**Fix:** clamp `constexpr float kMaxDeltaSeconds = 0.1F;` once in `GameplayLoop`, apply to all ticks.

### E-Run-3. Fast projectiles tunnel through thin castle colliders
**File:** `Engine/src/Runtime/GameplayLoop.cpp:135-211`

Two collision models in one tick: gravity path = point-vs-AABB, non-gravity = sphere-of-radius-0.6-vs-point. Catapult speed = 22 units/s, dt = 0.033 s → ~0.7 units/step, bigger than a 1-unit castle wall. No swept test, no sub-iteration. Boulders can pass through walls without damage.

### E-Run-4. `followedEntity` becomes a dangling pointer if the script deletes it
**File:** `Runtime/src/main.cpp:518-519, 580-581, 644-647`

`const SceneEntity* followedEntity = scene.findEntity(...)` captured once per frame *before* `tickScripts`. If a script deletes the camera entity this frame, the rest of the frame dereferences a dangling pointer. UB potential.

### E-Run-5. Inventory save/load is asymmetric — round-trip loses material/scale/color
**File:** `Runtime/src/main.cpp:143-228`, `Engine/include/GameForger/Runtime/GameplayLoop.hpp:38-48`

Write path emits only `itemName`/`iconPath`/`count`; read path constructs `InventoryItem` with all 8 fields default-initialized. Pickup-then-save-then-reload visually loses item identity.

### E-Run-6. `Load` doesn't reset session state
**File:** `Runtime/src/main.cpp:684-712`

`gameplay.heldItemEntityName`, `gameplay.playerOperatingCatapult`, `gameplay.gameOverMessage` survive a load. New game's scripts see stale session state; stale `gameOverMessage` silently persists.

### E-Run-7. Camera look state not reset on Load
**File:** `Runtime/src/main.cpp:684-712`

`gameCameraLookYawDegrees` / `gameCameraLookPitchDegrees` persist. Loaded game starts looking sharply up-and-right if the player was at save time.

### E-AI-1. AI request body embeds unescaped config values
**File:** `Editor/src/AIProviderClient.cpp:148-152`

Model string is read raw from JSON and concatenated into the request body with no `escapeJson`. Any `"`, `\n`, `\` in a model name produces an invalid body that providers reject with 400.

### E-AI-2. WinHTTP headers length is character count, not byte count
**File:** `Editor/src/AIProviderClient.cpp:179-180`

```cpp
WinHttpSendRequest(requestHandle, headers.c_str(),
    static_cast<DWORD>(headers.size()), ...);
```
For ASCII-only `Content-Type` / `Authorization` headers today this happens to work. Any localized header name silently breaks.

### E-UI-1. `ScriptCreatorState::previewBuffer` is 8 KiB hard-capped
**File:** `Editor/src/main.cpp:537, 5086-5093, 5097-5098`

```cpp
std::array<char, 8192> previewBuffer{};
...
std::snprintf(scriptCreator.previewBuffer.data(), scriptCreator.previewBuffer.size(), "%s", ...);
```
Generated Lua scripts over 8 191 bytes silently truncate; the truncated text is written to disk via Save & Attach. `ScriptEditorState::buffer` has the same issue at 16 384.

### E-UI-2. OpenGL 4.6 context requested but never verified
**File:** `Editor/src/main.cpp:6660-6684, 6730`

`gladLoadGL` returns the GLAD loader version, not the context's actual major.minor. If the driver returns 4.5 or lower, every shader compile fails and the viewport shows the only fallback `ImGui::TextUnformatted("Viewport OpenGL indisponible.")`.

**Fix:** `glGetIntegerv(GL_MAJOR_VERSION, &major); glGetIntegerv(GL_MINOR_VERSION, &minor);` and bail/lower GLSL if below 4.6.

### E-UI-3. `ImGuiInputSource::isKeyPressed` semantics differ from script expectation
**File:** `Editor/src/ImGuiInputSource.cpp:54-58`

```cpp
return key != ImGuiKey_None && ImGui::IsKeyPressed(key, false);
```
`IsKeyPressed(..., false)` fires only on the transition frame. A Lua author writing `while self.input:isKeyPressed("W") do ... end` gets one frame of truth. The header says it's ImGui's transition-only; `ScriptGenerator.cpp:108-111` doesn't warn the script author. Add an `isKeyDown` mapping or rename to `wasKeyPressedThisFrame`.

### E-UI-4. `escapeJson` in AI provider drops `\r`, doesn't escape `\t`/`\b`/`\f`
**File:** `Editor/src/AIProviderClient.cpp:72-92`

Same family of bugs as E-Scene-2. Anthropic/OpenAI gateways with strict JSON parsers reject these requests.

### E-Script-4. `luaEntitySetPosition` / `SetRotation` swallow "entity missing" silently
**File:** `Engine/src/Editor/ScriptRuntime.cpp:70-79, 89-98`

If an entity has been deleted mid-Play, the script's `self.entity:setPosition(...)` silently does nothing. Scripts can't distinguish "no-op because entity is gone" from "success."

### E-Script-5. Lua chunk partial-failure leaks globals to `_G`
**File:** `Engine/src/Editor/ScriptRuntime.cpp:721-726`

On `lua_pcall` error, any top-level `SOME_CONSTANT = 1` defined before the error remains in `_G`. Future scripts sharing those names inherit broken state.

### E-Scene-4. `replaceEntities` doesn't advance `nextEntityId_` past preserved ids
**File:** `Engine/src/Editor/EditorScene.cpp:628-631`

Document restore (snapshot/undo) preserves entity ids but doesn't bump `nextEntityId_`. Next `CreateEntityCommand` allocates an id that collides with an existing entity — `findEntity(int)` returns whichever appears first.

### E-Import-1. Skinned import silently drops non-skinned meshes
**File:** `Engine/src/Editor/ModelImport.cpp:206-210`

When `sceneHasSkin()` returns true, only `appendSkinnedMeshes` runs; any mesh without bones is skipped entirely. A rigged character with a static weapon/prop loses the prop on import.

### E-Import-2. `InverseBindMatrix` may be identity for non-skinning helper bones
**File:** `Engine/src/Editor/ModelImport.cpp:411-433`

Documented, but worth flagging that downstream code consuming `bones[]` must handle "unused slot, identity" explicitly (assertion in debug would help).

### E-Import-3. No recursion depth cap on Assimp scene traversal
**File:** `Engine/src/Editor/ModelImport.cpp:85-103, 192-257, 266-326`

A pathologically deep scene graph (some exporters produce 1000+ levels) will overflow the stack and crash. Easy mitigation: depth cap ~64.

### E-Path-1. `weakly_canonical` doesn't resolve symlinks
**File:** `Engine/src/Core/ProjectPaths.cpp:49, 56, 62`

Lexical normalization only — a symlink inside `Game/Scripts` pointing outside the project passes the containment check while the OS follows the symlink. Document the limitation or use `canonical` for stricter confinement.

### E-Path-2. `toLowerAscii` is only ASCII-correct
**File:** `Engine/src/Core/ProjectPaths.cpp:10-15`

Windows uses Unicode-aware case folding; non-ASCII path components don't compare correctly. Use ICU's `u_strFoldCase` or `CompareStringEx` with `NORM_IGNORECASE`.
